## Ключевые технические решения

| Вопрос                | Решение                                                                               | Обоснование                                      |
| --------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Структура репозитория | Монорепо: `client/` + `server/`, npm workspaces                                       | Общие типы, один деплой, простота                |
| FSRS                  | Библиотека [`ts-fsrs`](https://github.com/open-spaced-repetition/ts-fsrs)             | Каноничная TS-реализация, не пишем алгоритм сами |
| Авторизация web       | Telegram Login Widget → `POST /auth/telegram` → проверка hash → JWT (httpOnly cookie) | Единственный способ входа по спеке               |
| Авторизация бота      | По `telegram_id` из grammY-контекста, тот же слой users                               | Бот и сайт — один аккаунт                        |
| AI-провайдер          | OpenAI SDK, один вызов на слово со structured output (JSON schema)                    | Одна модель заполняет все поля карточки за раз   |
| Валидация API         | `zod` в middleware                                                                    | Общие схемы для client/server                    |
| Миграции              | Prisma Migrate                                                                        | Стандарт для Prisma                              |
| Frontend-роутинг      | Хэш-роутер или маленький самописный history-роутер, без фреймворков                   | По спеке: без React/Next                         |

## Этап 0. Каркас проекта ✅

1. `git init`, `.gitignore`, `README.md`.
2. npm workspaces: корневой `package.json`, пакеты `client/` и `server/` (+ опционально `shared/` для типов DTO).
3. `server/`: TypeScript, Express, tsx для dev-режима, ESLint + Prettier.
4. `client/`: Vite (vanilla-ts template).
5. `docker-compose.yml` с PostgreSQL 16 для локальной разработки.
6. `.env.example`: `DATABASE_URL`, `OPENAI_API_KEY`, `TELEGRAM_BOT_TOKEN`, `JWT_SECRET`.

**Результат:** `npm run dev` поднимает API + фронт, БД в Docker.

---

## Этап 1. Схема БД (Prisma) ✅

Модели:

- **User** — `id`, `telegramId` (unique), `username`, `firstName`, `photoUrl`, `createdAt`.
- **Notebook** — `id`, `userId`, `title`, `description?`, `emoji?`, `createdAt`; счётчик слов считаем запросом, не храним.
- **VocabularyItem** — `id`, `userId`, `text`, `language`, `translation`, `partOfSpeech`, `explanation`, `examples` (Json), `synonyms` (Json), `antonyms` (Json), `difficulty` (CEFR: A1–C2), `status` (`NEW | LEARNING | REVIEW | MASTERED`), поля FSRS-состояния (`stability`, `difficulty`, `due`, `lastReview`, `reps`, `lapses`, `state`), `aiStatus` (`PENDING | READY | FAILED`), `createdAt`. Unique: `(userId, text, language)`.
- **NotebookItem** — связь M:N `notebookId` + `vocabularyItemId`, `addedAt`.
- **Review** — `id`, `vocabularyItemId`, `rating` (`AGAIN | HARD | GOOD | EASY`), `reviewedAt`, снапшот FSRS-состояния.

**Результат:** `prisma migrate dev` создаёт схему; сид-скрипт с тестовыми данными.

---

## Этап 2. Авторизация ⬜

1. `POST /auth/telegram` — валидация данных Login Widget (HMAC-SHA256 по bot token), upsert пользователя, выдача JWT в httpOnly cookie.
2. Middleware `requireAuth` — проверка JWT, `req.user`.
3. `GET /auth/me`, `POST /auth/logout`.
4. На фронте: страница входа с Telegram-виджетом, редирект в кабинет.

**Результат:** вход через Telegram работает end-to-end.

---

## Этап 3. Наборы (Notebooks) ⬜

1. CRUD API: `GET/POST /notebooks`, `PATCH/DELETE /notebooks/:id` (с проверкой владельца). `GET /notebooks/:id` — набор + слова + статистика.
2. Frontend: список наборов, создание/переименование/удаление, страница набора.

**Результат:** пользователь управляет наборами через сайт.

---

## Этап 4. Импорт слов + AI-пайплайн ⬜

Ядро продукта.

1. `POST /vocabulary/import` `{ notebookId, text }`:
   - разбивка по строкам, trim, удаление пустых и дубликатов;
   - поиск существующих `VocabularyItem` пользователя → просто привязка к набору;
   - для новых: создание записей со статусом `aiStatus=PENDING`, ответ сразу (не ждём AI).
2. Фоновая обработка (простая очередь в процессе, без Redis в MVP): для каждого PENDING-слова один вызов OpenAI со structured output → язык, часть речи, перевод, примеры, синонимы, антонимы, объяснение, CEFR-уровень → `aiStatus=READY`. Ретрай ×2, при неудаче `FAILED`.
3. `GET /vocabulary/:id`, `PATCH /vocabulary/:id` (ручное редактирование), `DELETE`, `POST /vocabulary/:id/regenerate`.
4. Frontend: большое поле массового ввода на странице набора, список карточек с индикатором обработки (поллинг статуса), страница карточки с редактированием.

**Результат:** вставил список слов → через секунды готовые карточки.

---

## Этап 5. Повторения (FSRS) ⬜

1. Интеграция `ts-fsrs`: новые слова получают начальное состояние при создании.
2. `GET /review/today` — слова с `due <= now` + порция новых (лимит настраиваемый, по умолчанию 20 повторений / 10 новых в день).
3. `POST /review/result` `{ itemId, rating }` — прогон через FSRS, обновление состояния, запись в `Review`.
4. Frontend: экран повторения — слово → «показать ответ» → перевод/объяснение/пример/синонимы → 4 кнопки оценки. Прогресс сессии, экран завершения.

**Результат:** полный цикл интервального повторения.

---

## Этап 6. Dashboard ⬜

1. `GET /dashboard`: слов всего, к повторению сегодня, новых слов, последние наборы, распределение по статусам.
2. Frontend: главный экран с этими блоками и кнопкой «Начать повторение».

---

## Этап 7. AI Chat ⬜

1. `POST /ai/chat` — чат с системным промптом «AI-тьютор» + инструменты (tool use): поиск по словарю пользователя, список наборов, слова на сегодня. Стриминг ответа (SSE).
2. История чата: в MVP — только в рамках сессии (без персистентности), таблицу сообщений отложить на v2.
3. Frontend: страница чата с историей и стримингом.

**Результат:** «Проверь меня по словам из Ведьмака» работает.

---

## Этап 8. Telegram-бот (grammY) ⬜

1. Long polling в dev, webhook в prod. Привязка к аккаунту по `telegram_id`.
2. Команды: `/start`, `/add <слово|список>` (в набор по умолчанию или выбор набора inline-кнопками), `/review` — повторение прямо в чате (inline-кнопки оценки), `/notebooks`.
3. Свободный текст → AI-чат (тот же сервис, что этап 7).
4. Ежедневное уведомление о словах к повторению (cron внутри сервера, настройка времени — в v2).

**Результат:** бот как полноценный второй интерфейс.

## Этап 9. Настройки и полировка ⬜

1. Страница настроек: язык интерфейса (ru/en), дневные лимиты повторений, родной язык (язык переводов).
2. Обработка ошибок и пустых состояний на всех экранах; лоадеры.
3. Rate limiting на AI-эндпоинты; логирование (pino).

## Этап 10. Деплой ⬜

1. Dockerfile (multi-stage: build client → раздача статики Express-ом).
2. Прод-окружение: любой VPS / Railway / Fly.io + managed Postgres.
3. HTTPS обязателен (требование Telegram Login Widget и webhook).
4. Миграции при деплое: `prisma migrate deploy`.

## Открытые вопросы (решить до соответствующего этапа)

1. **Родной язык пользователя** — на какой язык переводить? В MVP: считаем русский по умолчанию, настройка на этапе 9. _(нужно до этапа 4)_
2. **Направление изучения** — слово→перевод или оба направления при повторении? В MVP: только слово→перевод. _(до этапа 5)_
3. **Модель OpenAI** — какая модель для пайплайна карточек (дешёвая) и для чата (умнее)? Решить на этапе 4 по цене/качеству.
4. **Слово в нескольких наборах** — при удалении из набора карточка остаётся в словаре? Предлагаю: да, удаление из набора ≠ удаление карточки. _(до этапа 3)_
5. **Локальная разработка без HTTPS** — Telegram Login Widget требует домен; для dev использовать тестовый режим/ngrok или dev-заглушку авторизации. _(до этапа 2)_
